Data plane

Modality care before fusion

profile

Sparsity, entropy, finite-value coverage, dynamic range, temporal change, and pairwise alignment are surfaced before the runtime leans on a modality.

provenance

Payloads, metadata, and modality bodies receive separate deterministic receipts so repeated runs remain comparable.

alignment

Timed observations can be grouped into corroborated windows instead of being left as isolated fragments.

intercept

A pre-inference tensor guard now measures entropy, spatial frequency, saturation, and modality risk before the model route opens.

jobs

Long-running cleanup and batch inference runs are stored with status transitions and result payloads in a persisted SQLite lane.

drift

Reviewed population baselines can be saved, listed, and checked before a new cohort is folded into the default lane.

bias

A sixty-category taxonomy keeps bias tied to entry points such as collection, measurement, retrieval, interface, and governance.

Catalog plane

Schema changes can be reviewed before they become operational drift

registration

Dataset contracts now carry owner, modality, partition keys, primary keys, and field-level schemas in a persisted store.

fingerprinting

Canonical schemas receive deterministic fingerprints, using the Rust lane when it is available.

evolution

Candidate schema revisions are classified into additive and breaking changes before a pipeline rolls forward.

connectors

Local CSV, local Parquet, S3-backed Parquet, local NDJSON, HTTP JSON, HTTP NDJSON, and public HTML rows can be pulled into the runtime through one typed registration surface.

benchmarks

Each connector run records fetch time, parse time, bytes read, and rows per second so a data path can be inspected instead of simply trusted.

replay

Persisted pipeline runs can now be exported and replayed to compare provenance and summary-shape stability against the current runtime.

Governance plane

Enterprise reality can be compiled and checked

ontology

API schemas, workflow notes, and governance artifacts can be ingested into a persisted ontology snapshot with entities, relations, and compiled constraints.

stewardship

Lifecycle policies, change-control records, and supply-chain snapshots keep review cadence, data half-life, and removal intent visible as persisted backend records.

liability

Route traces are compared against compiled constraints such as encryption requirements, regional transfer blocks, reviewed lanes, and region pins.

attestation

The runtime can return an evidence bundle covering OpenAPI digest, generated clients, runtime schema, Rust core presence, and persisted store counts.

proof bundle

A second surface summarizes route count, test count, verification commands, supported connector kinds, and artifact presence in one typed response.

readiness

A companion report states where evidence is complete, where more proof is still needed, and which operating boundaries remain intentionally narrow.

execution journal

Recent export and verification runs are persisted with commands, artifact states, and lane counts so operational memory is not lost after one local session.

Operations

Local stack

The local operations path is intentionally modest and direct.

  • FastAPI service
  • Rust multimodal core
  • Qdrant for vector storage when enabled
  • Typed connector pulls for file, object-store, HTTP, and public web sources
  • Persisted stewardship lanes for retention, change control, and supply-chain review
  • S3-shaped Parquet intake with caller-managed credentials
  • Public-page intake with allowlists, robots checks, and byte caps
  • Compiled recipe manifests with checked export and validation steps
  • Prometheus scrape configuration
  • OpenAPI export and generated client surfaces
  • Persisted connector, drift, pipeline, and ontology stores
  • Bias taxonomy, runtime attestation, and readiness reporting
  • Persisted async jobs for longer-running work
  • CI for lint and tests
  • TypeScript SDK for downstream consumers
  • Pages deployment for the public static surfaces
