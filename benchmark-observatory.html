Reference workload

One lane, many checks, no need for guesswork.

This page follows a single generated workload across connector-backed ingest, pipeline sealing, replay verification, concurrent batch work, recipe compilation, and proof refresh. It is the shortest path from “does the backend actually run?” to something you can inspect.

What to look for
  • whether connector ingest produced a persisted pipeline run
  • whether replay returned to the same sealed frame chain
  • whether batch execution and recipe compilation stayed close to the same workload
  • whether the proof export refreshed from the same backend edge
A benchmark is only useful here if it stays close to the routes, stores, and files the repository actually uses.
